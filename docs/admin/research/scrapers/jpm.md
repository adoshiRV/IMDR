## URL patterns

### Article viewer
```
https://markets.jpmorgan.com/jpmm/research.article_page?action=open&doc={DOC_ID}
```

`DOC_ID` shape: `{PUBCODE}-{ID}-{VERSION}` — e.g. `GPS-5311509-0` for
a Global Markets Strategy report. All 25 results in the Flagship-Latest
page-1 sample shared the `GPS-XXXXXXX-0` prefix because that view is
narrowly scoped; other PUBCODEs surface in other queries (`EMR-`,
`KAL-` for Kaltura video, etc.).

### PDF URL — **direct-PDF-B (confirmed 2026-05-29)**
```
GET https://markets.jpmorgan.com/research/PubServlet?action=open&doc={DOC_ID}.pdf
```

Returns the raw PDF binary:
- `content-type: application/pdf`
- `content-disposition: inline; filename=…<auto-generated>.pdf`
- Authed via the same session cookies as the GraphQL listing call.

Crawler should construct this URL during discovery from each result's
`id` field (no second metadata call needed). See
`playground/research/jpm_verify_pdf_url.py` for the candidate-URL
verification script — 5 patterns scraped from the viewer HTML,
`PubServlet` was the only one returning `%PDF`.

The other tested patterns (kept here so we don't re-try them):
- `/research/ArticleServlet?doc={id}.pdf` → 200 + `text/html` (HTML wrapper)
- `/research/content/{id}.pdf` → 200 + tiny HTML (placeholder)
- `/research/CFP?page=output&action=open&doc={id}&format=PDF` → 200 + HTML
- `/research/CFP?page=article_page&action=open&doc={id}.pdf` → 200 + HTML

### Listing / search (URL → backend)
The SPA route is `/jpmm/search?query={base64(querystring)}`, where
`querystring` carries the human-facing saved view (display name,
facets, sort). The browser then POSTs the actual query to the GraphQL
endpoint below.

## Listing API — GraphQL (Phase 2 confirmed)

> **Why GraphQL over the higher-scoring `Home.model.json`?** The
> `probe_listing_apis.py` log scored
> `/jpmcp-cm/content/jpm-cp/research/Index/Home.model.json` highest
> (2038, vs GraphQL 1054). That endpoint is the AEM page-config blob
> for the research-home dashboard (sidebars, hero tiles, widget
> layout) — it happens to embed lots of doc UUIDs but it does **not**
> page the underlying corpus. GraphQL is what backs every actual
> search / listing view in the SPA, and is the only one of the probed
> endpoints with per-doc metadata (title/synopsis/analysts/etc) on a
> paginated, date-filterable contract. A sibling endpoint
> `/research/controller/aem/query` returns the same response shape but
> only fires for widget-level lookups (the Phase-2 probe of the
> Flagship-Latest search page never triggered it); we ignore it.

**Endpoint:** `POST https://markets.jpmorgan.com/research/controller/graphql/query-v2`

**Auth:** session cookies (Playwright persistent profile handles this
automatically) **plus** a custom `janus_user` header carrying the
portal username — see headers below. The SPA injects `janus_user` on
every GraphQL call; we have not yet confirmed whether the server
rejects calls without it, but the crawler should send it to be safe.

**Headers used by the SPA:**
- `content-type: application/json`
- `accept: */*`
- `janus_user: <portal-username>` — e.g. `janus_user: arjund`. Source
  from `IMDR_RESEARCH_JPM_USERNAME` in the crawler; do **not** hard-code.
- `referer: https://markets.jpmorgan.com/mcp-home/search?…` (cosmetic)

**Request body:**
```json
{
  "operationName": "research",
  "query": "query research($businessGroupClassification: …) { … }",
  "variables": {
    "businessGroupClassification": "ALL",
    "startDate": null,
    "endDate": "2026/05/29 23:59",
    "start": 1,
    "pageSize": 25,
    "sortOrder": "PUBLICATION_DATE",
    "sortDirection": "DESCENDING",
    "exactMatch": false,
    "searchText": "",
    "relevanceText": "",
    "researchQueryNodeChildren": [
      {"item": "SEARCHABLE",              "operator": "EQUALS",     "values": "Y"},
      {"item": "AUDIENCE_TYPE_ENTITLEMENT","operator": "NOT_EQUALS", "values": "H-ShareRestricted"},
      {"operator": "OR", "children": [
        /* saved-view facets — for our crawler we drop this whole subtree
           and let the date filter do the work */
      ]}
    ]
  }
}
```

The exact full GraphQL `query` string is captured in
`playground/research/jpm_explore/graphql_capture_*.json` — copy from
there verbatim into the crawler.

**Required base filters (the SPA always injects these — leave them in):**
- `SEARCHABLE = Y`
- `AUDIENCE_TYPE_ENTITLEMENT != H-ShareRestricted`

**Pagination:** `start` is 1-indexed, `pageSize` was 25 in the wild
(probably can push to 100–200; the EXPORT UI says 1000-row cap so the
API likely accepts at least that).

**Date window:** `startDate`/`endDate` strings format
`"yyyy/MM/dd HH:mm"` (see `inputDateFormat` in the GraphQL query). For
the daily crawler: `endDate = today 23:59`, `startDate = since 00:00`.

**Sort:** `sortOrder: PUBLICATION_DATE | SCORE`,
`sortDirection: DESCENDING | ASCENDING`. Always use
`PUBLICATION_DATE DESCENDING` so we can early-stop when the last item
on the page is older than `since`.

### Per-result fields (used downstream)

| GraphQL field         | Example                                                | Crawler maps to                |
|-----------------------|--------------------------------------------------------|--------------------------------|
| `id`                  | `GPS-5311509-0`                                        | `ReportRef.uuid`               |
| `title`               | `Flows & Liquidity`                                    | `ReportRef.title`              |
| `subtitle`            | `The share of retail investors in US equity…`          | append to title for display    |
| `synopsis`            | `While the share of retail investors…`                 | classifier context             |
| `publicationDate`     | `Wed May 27 17:27:27 UTC 2026` (RFC-ish string)        | `ReportRef.publish_date`       |
| `documentFormats[]`   | `[{mimeType: "text/html"}, {mimeType: "application/pdf"}]` | filter for `application/pdf` |
| `documentType`        | `Document` \| `Video`                                  | drop `Video` in discovery filter |
| `isResearch`          | `Y` \| `N`                                             | drop `N` in discovery filter   |
| `contentTypes`        | `["PUBNOT"]`                                           | additional admin filter        |
| `pageCount`           | `32`                                                   | sanity check during fetch      |
| `analysts.results[]`  | `[{sid, displayName, primary, active, publishingAnalyst, businessGroup}]` | classifier `tags`     |
| `businessGroup`       | **OBJECT** — `{displayName: "Global Markets Strategy", subCategoryLabel: "Research", overrideDisplayName: …}` — use `.displayName` (or `.overrideDisplayName` when set) | classifier `asset_class` hint  |
| `companies.results[]` | `[{ricCode: {ticker, exchange}}]`                      | single-name equity signal      |

### Aggregations (free taxonomy — use for classifier mapping)

The same GraphQL call returns aggregation buckets that double as a
controlled vocabulary. Snapshot from Flagship-Latest (9,404 docs):

| Aggregation       | Buckets | Top values                                             |
|-------------------|---------|--------------------------------------------------------|
| `ASSET_CLASS`     | 4       | FixedIncome (7440), Currency (3328), Commodity (2968), Equity |
| `REGION`          | 10      | Global, NorthAmerica, Europe, Australasia, Japan, AsiaPacific, LatinAmerica, EMEA (label "CEEMEA"), Africa, MiddleEast (label "MENA") — **no "EmergingMarkets" bucket** |
| `COUNTRY`         | 95      | US (2265), CH, GB, JP, …                              |
| `BUSINESS_GROUP`  | 28      | Economic Research, Markets Strategy, Rates Strategy, Equity Research, … |
| `SECTOR`          | 172     | Consumer Discretionary, Industrials, Financials, …    |
| `COMPANY`         | 654     | RIO.L, SOGN.PA, CRDI.MI, …                            |
| `ANALYST`         | 298     | Mika Inkinen, Bruce Kasman, Nikolaos Panigirtzoglou   |
| `DOCUMENT_TYPE`   | 0 (in this sample) |                                                |

For the classifier in [`classifiers/jpm.py`](../../../playground/research/ingest/classifiers/jpm.py) (TBD):

- `asset_class` ← `ASSET_CLASS` bucket of result's classification (or
  derive from `businessGroup` if `ASSET_CLASS` not on the result).
- `country_code` ← `COUNTRY` (already ISO-style "US", "GB", "JP"…).
- `region` ← `REGION` (already in our taxonomy after mapping
  "NorthAmerica"→"NA" etc.).
- `tags` ← `SECTOR`, `BUSINESS_GROUP`, `documentType`, primary analyst
  `sid`, primary `displayName`.
- `context` ← `title` + `subtitle` + `synopsis`.

**Note**: each result's full taxonomy fields are not in the basic
GraphQL response shape captured here — the response gives aggregations
across the search, but individual results only include
`analysts`/`companies`/`businessGroup`/`documentType` /`title` /
`synopsis`. To get per-doc `ASSET_CLASS`/`REGION`/`COUNTRY` we may need
a richer per-doc query (TBD — check whether expanding the GraphQL
selection set returns them, before resorting to a second call).
